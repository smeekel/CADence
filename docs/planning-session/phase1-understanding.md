# Phase 1: understanding of the inputs

Planning session, Phase 1 (read inputs, toolchain check). Inputs read in full: `CURSOR_PLAN_PROMPT.md`,
`docs/spec/cad-functional-requirements.md` (v0.2), all 13 files in `docs/notepads/`, all 9 files in `.cursor/rules/`,

`docs/FOLDER_STRUCTURE.md`. Date of check: 2026-11-11.

## 1. Summary of the inputs

1. **Product:** APP (placeholder name) is a clean-room, offline, Windows-first desktop CAD application that unites
   parametric MCAD (sketch, part, assembly, drawing, sheet metal, weldment, motion) and ECAD (library, schematic,
   SPICE, PCB, fabrication outputs) in **one parametric model**; the PCB-in-enclosure reference scenario (T-14) is the
   reason it exists and the release gate from S6.
2. **Stack (D-01 … D-13):** C++26 via `/std:c++latest`; VS 2026 `APP.slnx` + one `.vcxproj` per module + vcpkg
   manifest mode, no CMake; Qt 6 Widgets; OCCT behind `geom::`; own sketch and mate solvers (Eigen); Chrono; ngspice;
   Clipper2; nlohmann `ordered_json` for JSON and BSON; lib3mf; GoogleTest; OpenGL 4.5 behind `render::Device`; Embree.
3. **Architecture:** 18 modules with a strict one-way layering (A-01) checked by `scripts/check-layering.ps1`;
   headless-first (A-02); every data change is a journaled command with undo (A-03); UUID v7 identities (A-04);
   kernel adapter (A-05); persistent topological naming (A-06); one regeneration DAG across all documents and links
   (A-07); one unit-aware expression language (A-08); PCB geometry in int64 nm (A-09); non-blocking UI (A-10);
   factories for extensibility (A-11).
4. **File format:** open, documented JSON folder (`.apj`) and BSON single file (`.apb`), lossless and byte-stable;
   deterministic output; fixed magic UUID `d9a3877a-3f27-4df8-9528-f8dfde59773d` first in every file; semver
   migrations; unknown fields preserved; libraries resolved project → user → global (F-10).
5. **Licence and clean room:** GPL-3.0-or-later, SPDX header in every source file, provenance log for any reuse;
   nothing from proprietary CAD products; paid standards never reproduced; no network code at runtime (P-03).
6. **Quality bar:** every `Accept:` criterion becomes a named automated test; golden data generated by command scripts;
   `/W4 /WX`; no fake completion; zero Doxygen warnings; strict owner code style (Allman braces, `if( a == b )`,
   aligned `=` and declarations, blank lines between blocks).
7. **Stages:** S0 foundation → S1 sketcher → S2 parts → S3 assemblies → S4 libraries + schematic → S5 PCB →
   S6 MCAD↔ECAD (reference scenario green) → S7 drawings + manufacturing → S8 advanced modeling → S9 simulation →
   S10 scale + polish; each ends with a stage gate and human review.
8. **Spikes:** eight time-boxed spikes, each ending in an ADR before dependent work: SP-1 toolchain, SP-2 topological
   naming, SP-3 sketch solver, SP-4 mate solver, SP-5 router, SP-6 pours, SP-7 links, SP-8 large assemblies.
9. **Notepads** add implementation contracts the spec leaves open (error model, command and regeneration interfaces,
   document envelope, `TopoRef` shape, rule query language, UI tokens); items marked **(proposed)** need an ADR.
10. **This session** produces the folder-structure document, a compiling scaffold, the implementation checklist with
    full requirement coverage, stage plans, traceability, risks and ADRs, then stops for review.
