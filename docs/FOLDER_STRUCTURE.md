# Folder structure {#folder-structure}

This page shows the repository as it will look by Stage 10, with a one-line purpose for every folder. It follows
spec section 5.1 (module layout), section 4.4 (build system B-01 to B-07) and the notepad
`docs/notepads/Architecture_and_Build.md`. Module dependencies are not repeated here; they are defined in
`.cursor/rules/030-architecture-layering.mdc` and enforced by `scripts/check-layering.ps1`.

## Legend

| Marker | Meaning |
|---|---|
| `[exists]` | Already in the repository before the scaffold (planning kit) |
| `[now]` | Created by the scaffold in the planning session |
| `[S0]` … `[S10]` | First appears in that stage (created by the checklist step that needs it) |
| `[on demand]` | Created only when first needed (for example on the first reuse of third-party code) |
| `[build]` | Generated by builds or scripts; never committed (listed in `.gitignore`) |
| `(proposed)` | Not named in the spec or notepads; needs confirmation by ADR during planning |

A folder marked `[now]` may still be almost empty (a `README.md` or `.gitkeep`); its content arrives in the stage noted
in its description. Sub-folders inside a module or test folder are the ones named in the deliverables of
`docs/IMPLEMENTATION_CHECKLIST.md`; their marker is the stage of the first step that creates them.

## Contents of every module folder

Each `src/<module>/` folder created now contains:

- `<Module>.vcxproj` and `<Module>.vcxproj.filters`: file list, project references and module-specific settings only.
- `Module.h` and `Module.cpp`: a documented `moduleInfo()` returning the module name and version.
- `README.md`: the module's purpose and its allowed dependencies (Doxygen module page).

Each `tests/<module>/` folder contains `<Module>.Tests.vcxproj` with one passing GoogleTest.
